8. **[WARN] Profile and theme implemented; executable verification blocked.** `src/app/profile.tsx:25–61` selects/copies a picture, saves the username, and updates the theme. `src/lib/store.tsx:31–35` supplies shared colors used by all three screens and tabs (`src/app/_layout.tsx:11`). See finding 14 for long-range performance.
10. **[FAIL] Persistence has a data-loss window during native replacement.** `src/lib/storage.ts:18–24` writes a pending file then moves it over the saved file. The installed iOS implementation of that operation deletes the destination before moving the pending file (`node_modules/expo-file-system/ios/Legacy/FileSystemLegacyModule.swift:138–141`). A failure or process termination between those operations leaves no main file. `src/lib/storage.ts:14–16` then returns initial empty data and never recovers the pending file. This can lose all previous expenses/categories/profile on reopening. The normal success path does serialize all required data; `src/lib/store.tsx:19–26` commits in-memory changes only after storage succeeds, and expense/category/profile forms retain their local inputs and display errors. Those useful safeguards do not protect the on-disk replacement window. Theme failure also rolls the switch back without retaining the intended value (`src/app/profile.tsx:50–52,61`), requiring the user to select it again.
